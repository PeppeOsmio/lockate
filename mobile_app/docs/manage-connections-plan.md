# Named connections + dedicated Manage Connections page

## Context

Connections today are identified only by a raw `url` (plus vestigial, always-null `username`/`authToken` fields) — there's no way to give a server a recognizable label. The only place to select/add/edit a connection is `ConnectionsDialog`, which crams selection, adding, and per-row editing into one small modal. There is also no dedicated way to *delete* a connection except the "Logout" flow, which deletes whatever is currently selected as a side effect of disconnecting.

This plan adds a required `name` field to connections, and splits responsibilities cleanly:
- **`ConnectionsDialog`** (opened from Home's top bar): select a connection to use, or add a new one. No more per-row edit icon.
- **New `ManageConnectionsScreen`**: the one place to see all connections, edit any of them, or delete any of them.

This is the app's first Room schema change, so it also establishes the migration approach, and it fixes a latent bug where `HomePageViewModel` never refreshes its connection list after navigating away and back (which would otherwise let you delete the active connection from the new page and return to a stale/broken Home).

## Data layer

- **`domain/Connection.kt`**: add `val name: String`.
- **`data/anonymous_group/database/ConnectionEntity.kt`**: add `@ColumnInfo(defaultValue = "") val name: String`. Empty-string default (not a placeholder like "Unnamed") — display-time fallback to `url` stays a UI concern.
- **`AppDatabase.kt`**: bump `version = 2`, add `autoMigrations = [AutoMigration(from = 1, to = 2)]`. A single additive defaulted column qualifies for Room's `@AutoMigration`, so no hand-written `Migration` class is needed (none exist in the project yet — this is the first). `app/schemas/.../2.json` will be generated by the build; commit it alongside.
- **`data/anonymous_group/mappers/ConnectionMapper.kt`**: thread `name` through `toEntity`/`toDomain`.
- **`dao/ConnectionDao.kt`**: change `listConnections()` to `ORDER BY name COLLATE NOCASE` (case-insensitive alphabetical, matches "recognize more easily"). Leave `getFirstConnection()` (`ORDER BY id ASC LIMIT 1`) untouched — it's an internal fallback-selection query, not a user-facing list.
- **`service/ConnectionService.kt`**: no signature changes for `name` itself (callers just populate the field). This file does get one addition for the stale-state fix below.

## `ConnectionSettingsScreen` / `ViewModel` / `State` (existing add-or-edit form)

- `ConnectionSettingsScreen.kt`: add a Name `OutlinedTextField` above the URL field, same shape/wiring as the URL field.

## New `ManageConnectionsScreen` (package `ui/screens/manage_connections/`)

Structural template: `ui/screens/anonymous_groups/AnonymousGroupsScreen.kt` + `AnonymousGroupsViewModel.kt` (list + per-item delete via confirm dialog + loading overlay + snackbar channel — reuse this shape, don't invent a new one).

- **`ManageConnectionsState.kt`**: `connections: List<Connection>? = null`, `isLoading: Boolean = true`, `showLoadingOverlay: Boolean = false`, `selectedIndexForDelete: Int? = null`, `showDeleteConfirmDialog: Boolean = false`.
- **`ManageConnectionsViewModel.kt`** (deps: `ConnectionService`, `AnonymousGroupService`):
  - `getInitialData()` → `connectionService.listConnectionSettings()`.
  - `selectForDelete(index)` / `unselectForDelete()` / `openDeleteConfirmDialog()` / `closeDeleteConfirmDialog()` — mirror the AG screen's `selectAnonymousGroup`/`openSureLeaveDialog` naming.
  - `deleteConnection()`: cascade exactly like today's `HomePageViewModel.disconnect()` — try `anonymousGroupService.leaveAllAG(id)`, fall back to `deleteAllAG(id)` on failure, then `connectionService.deleteConnection(id)`, then remove it from local state. If the resulting list is empty, send a one-shot `Channel<Unit>` (`navigateBackEvents`) so the screen pops back to Home. This ViewModel does **not** need to reason about reselecting the active connection — that's handled centrally (next section).
  - Standard `snackbarEvents: Channel<SnackbarErrorMessage>` for errors.
- **`ManageConnectionsScreen.kt`**: `Scaffold` + back-button `TopAppBar` titled "Manage connections" with a trailing "+" action that navigates to `ConnectionSettingsRoute(null, showBackButton = true)`; `LazyColumn` of rows (primary text `connection.name.ifBlank { connection.url }`, secondary text `connection.url`, trailing Edit + Delete `IconButton`s); inline delete-confirm `AlertDialog` and loading-overlay `Dialog`, copied verbatim from the existing repeated patterns (no shared `ConfirmDialog` composable exists in this codebase — stay consistent with that, don't introduce one here as a drive-by).

## Drawer entry point

Repoint the drawer's "Connection settings" `NavigationDrawerItem` (`HomePageScreen.kt:184-199`) to the new page: relabel to **"Manage connections"**, keep the `Icons.Default.Settings` icon, and change `onClick` to call `navigateToManageConnections()` (then close the drawer), dropping its current direct dependency on `ConnectionSettingsRoute`/`state.selectedConnectionId`. Today it silently jumps into an *edit* form for whatever's selected under a misleading label — the new page supersedes that and is a clearer, single entry point (the dialog's "Add new connection" and "Manage connections" cover the rest).

## Fixing stale Home state on delete

`HomePageViewModel`'s `connections`/`selectedConnectionId` are only loaded once in `init` — navigating to `ManageConnectionsScreen`, deleting the active connection, and returning to Home would otherwise leave Home showing a dangling deleted id. Fix by reusing this codebase's existing cross-layer sync pattern (`MutableSharedFlow`, as already used in `AnonymousGroupService`) rather than adding a new lifecycle-resume dependency:

- New `service/ConnectionEvent.kt`: `sealed class ConnectionEvent { data class ConnectionDeleted(val connectionId: Long) : ConnectionEvent() }`.
- `ConnectionService.kt`: add `_events: MutableSharedFlow<ConnectionEvent>` / `val events`, emit `ConnectionDeleted` at the end of `deleteConnection(id)`.
- `HomePageViewModel.kt`: in `init`, launch a collector on `connectionService.events` that, on `ConnectionDeleted`, removes the id from `state.connections`, picks a new `selectedConnectionId` if the deleted one was active (persisting it via `saveSelectedConnectionSettingsId`), and sends the onboarding-redirect nav event if no connections remain.
- Simplify `disconnect()`: after it calls `connectionService.deleteConnection(...)`, the same collector now handles updating `connections`/`selectedConnectionId` and the empty-list redirect — `disconnect()` no longer needs to duplicate that logic. This also fixes a small existing gap where `disconnect()` updates local state but never persists the new `selectedConnectionId` via `saveSelectedConnectionSettingsId`.
- Update the disconnect confirmation text to use `.name.ifBlank { .url }` for consistency.

## Verification

No Compose UI test harness exists in this repo (only stock placeholder tests), so verify manually via `./gradlew installDebug`:

1. Install **over** an existing v1 debug build (not a clean uninstall) to exercise the `AutoMigration`; confirm no crash and existing connections show with URL as the fallback label.
2. Add a new connection with a name; confirm it displays by name (not URL) in both `ConnectionsDialog` and `ManageConnectionsScreen`.
3. Edit a connection's name from `ManageConnectionsScreen`; confirm it updates in both places.
4. Try saving with a blank name → expect the "Please enter a name" snackbar, no save.
5. Confirm `ConnectionsDialog` no longer has a per-row edit icon, and its new "Manage connections" button navigates correctly.
6. Delete a non-active connection from `ManageConnectionsScreen` → its anonymous groups are gone, Home is unaffected.
7. Delete the *active* connection (others remain) → Home reselects a different connection automatically, and that selection survives an app restart.
8. Delete the last remaining connection → screen pops back to Home, which immediately redirects to onboarding.
9. Confirm the drawer item now reads "Manage connections" and opens the new screen.
10. Re-verify the "Logout"/disconnect flow still works end-to-end, since `disconnect()` was simplified to share the reselection path with the new deletion flow.
